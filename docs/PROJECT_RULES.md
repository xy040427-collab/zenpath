# 择境 ZENPATH — 项目开发总规则

> 本文档是所有开发工作的最高优先级规则。
> 无论是人类开发者还是 AI Agent，都必须遵守。
> 任何任务开始前，必须先读取本文档。

---

## 一、核心原则

1. **规格优先**：任何功能开发前必须先有 Spec（requirements.md → design.md → tasks.md → acceptance.md）。
2. **小任务优先**：一个任务只解决一个明确问题，不允许大范围重构。
3. **受控执行**：Agent 不能自由发挥，必须按 Spec、规则、验收标准执行。
4. **系统验收**：AI 不能自己宣布完成，必须通过 build、test、页面验收和报告。
5. **安全优先**：不得修改敏感文件，不得破坏已有功能。

---

## 二、绝对禁止事项

以下行为在任何情况下都不允许：

| 编号 | 禁止行为 | 说明 |
|------|---------|------|
| P-01 | 自己宣布完成 | Agent 不能说"已完成"，必须通过 build + 验收 |
| P-02 | 删除已有功能 | 不允许删除页面、路由、API、组件 |
| P-03 | 大范围重构 | 一次任务只能改一个小范围 |
| P-04 | 用 mock 冒充真实功能 | 不允许写假数据假装功能实现 |
| P-05 | 绕过真实数据逻辑 | 不允许 hardcode 返回值绕过业务逻辑 |
| P-06 | 跳过构建和测试 | build 失败 = 任务未完成 |
| P-07 | 为通过测试删除测试 | 不允许删测试来让 CI 变绿 |
| P-08 | 修改无关文件 | 只能改 Spec 中允许的文件 |
| P-09 | 擅自新增依赖 | 新依赖必须说明来源和必要性 |
| P-10 | 修改敏感文件 | 参见 `DO_NOT_CHANGE.md` S 级清单 |
| P-11 | 把失败说成成功 | 命令失败必须如实报告 |
| P-12 | 跳过最终报告 | 每次任务必须输出完整报告 |
| P-13 | 编造不存在的命令 | 命令不存在就报告"不存在" |
| P-14 | 修改 .env 或数据库 | 绝对禁止 |
| P-15 | 展示密钥原文 | API key、token、password 不得输出 |

---

## 三、任务执行要求

每次任务执行必须满足：

1. **有 Spec**：任务来自 Spec 或 Issue，不是聊天中的随口一说。
2. **有范围**：明确列出允许修改的文件和禁止修改的文件。
3. **有计划**：先只读分析，输出执行计划，等待确认。
4. **有执行**：小范围修改，每次只改一个明确问题。
5. **有验证**：
   - 前端：`cd frontend && npm run build` 必须通过
   - 后端：`uvicorn app.main:app` 必须能启动
   - 页面：核心页面无白屏、按钮可点击、路由可访问
6. **有报告**：输出修改文件、命令结果、测试结果、风险、未完成项。

---

## 四、完成判定标准

一个任务只有在以下条件全部满足时才能被认为完成：

- [ ] `npm run build` 构建通过（前端任务）
- [ ] 相关页面可正常打开，无白屏
- [ ] UI 无明显跑偏（布局、颜色、间距正常）
- [ ] 不影响已有页面和功能
- [ ] 无 mock 冒充真实功能
- [ ] 无新增无关依赖
- [ ] 未修改 Spec 禁止范围外的文件
- [ ] 已输出完整执行报告

**任何一项不满足 = 任务未完成。**

---

## 五、失败处理

当任务执行过程中遇到以下情况时，必须**立即停止并报告**：

- build 失败
- 页面白屏
- TypeScript 类型错误
- 无法启动后端
- 修改了禁止范围的文件
- 无法确定影响范围
- 发现 Spec 有歧义

**禁止在失败时继续执行或假装成功。**

---

## 六、代码质量底线

- 不允许 `any` 类型泛滥（TypeScript）
- 不允许 console.log 残留（调试用除外）
- 不允许注释掉的代码块残留
- 不允许重复定义已有组件
- 不允许绕过 TypeScript 类型检查（`@ts-ignore` 除非有充分理由）
- 后端不允许裸 except 捕获所有异常
- 后端不允许在代码中硬编码 API key

---

## 七、沟通规范

- Agent 发现 Spec 有歧义时，必须停下来请求澄清
- Agent 发现风险时，必须在报告中明确标注
- Agent 不确定影响范围时，必须扩大禁止修改范围
- Agent 遇到无法解决的问题时，必须停止并说明原因
