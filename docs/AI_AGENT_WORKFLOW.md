# 择境 ZENPATH — AI Agent 标准工作流

> 本文档定义了 AI Agent 在本项目中执行任务的标准流程。
> 所有 Agent 必须严格按此流程执行，不允许跳步。

---

## 标准流程

```
┌─────────────────────────────────────────────────┐
│  1. 读取任务 Spec                                │
│  2. 读取 PROJECT_RULES.md                        │
│  3. 读取 DO_NOT_CHANGE.md                        │
│  4. 读取 STYLE_GUIDE.md                          │
│  5. 读取 TESTING_GUIDE.md                        │
│  6. 读取 SECURITY_POLICY.md                      │
│  7. 只读分析（不修改任何文件）                     │
│  8. 输出执行计划                                  │
│  9. 等待用户确认                                  │
│  10. 小范围修改（按计划执行）                      │
│  11. 运行构建和测试                               │
│  12. 运行页面验收                                 │
│  13. 输出执行报告                                 │
│  14. 提交 PR（如适用）                            │
│  15. 等待人类 review                              │
│  16. 合并或拒绝                                   │
└─────────────────────────────────────────────────┘
```

---

## 各步骤详解

### 步骤 1：读取任务 Spec

- 读取 `specs/<feature>/requirements.md` — 了解需求
- 读取 `specs/<feature>/design.md` — 了解设计
- 读取 `specs/<feature>/tasks.md` — 了解任务拆分
- 读取 `specs/<feature>/acceptance.md` — 了解验收标准

如果任务来自 Issue，先确认是否有对应 Spec。没有则要求创建。

### 步骤 2-6：读取规则文档

必须按顺序读取以下文档：

1. `docs/PROJECT_RULES.md` — 总规则
2. `docs/DO_NOT_CHANGE.md` — 禁止修改清单
3. `docs/STYLE_GUIDE.md` — UI/代码风格
4. `docs/TESTING_GUIDE.md` — 测试验收标准
5. `docs/SECURITY_POLICY.md` — 安全策略

**不允许跳过任何文档。**

### 步骤 7：只读分析

- 不修改任何文件
- 不新增任何文件
- 不删除任何文件
- 分析当前代码结构
- 确认修改范围
- 识别风险点

### 步骤 8：输出执行计划

计划必须包含：

```
## 执行计划

### 目标
[一句话描述]

### 允许修改的文件
- 文件 1：修改原因
- 文件 2：修改原因

### 禁止修改的文件
- 文件 1：禁止原因

### 执行步骤
1. 步骤 1 描述
2. 步骤 2 描述

### 预期风险
- 风险 1：缓解方案

### 验证方式
- 命令 1
- 命令 2
```

### 步骤 9：等待确认

- 输出计划后**必须停止**
- 等待用户说"继续"或"确认"
- 不允许自行继续执行

### 步骤 10：小范围修改

- 按计划逐个修改文件
- 每个修改都要有明确目的
- 不允许超出计划范围
- 发现计划外问题 → 停止并报告

### 步骤 11：运行构建和测试

```bash
# 前端任务
cd frontend && npm run build

# 后端任务
cd backend && uvicorn app.main:app --port 3458
```

- build 失败 → 任务未完成，修复后重试
- 最多重试 3 次，仍然失败 → 停止并报告

### 步骤 12：运行页面验收

参照 `TESTING_GUIDE.md` 第四节。

### 步骤 13：输出执行报告

参照 `REPORT_TEMPLATE.md`。

### 步骤 14-16：PR 和 Review

- 在 Git 分支上提交
- 创建 PR
- 等待人类 review
- 合并或拒绝

## Agent 硬性约束

| 编号 | 约束 |
|------|------|
| W-01 | 不能直接做大任务，必须先拆分 |
| W-02 | 不能跨范围修改，只能改 Spec 允许的文件 |
| W-03 | 不能口头说完成，必须有 build + 验证 |
| W-04 | 每次都要列出修改文件清单 |
| W-05 | 每次都要列出未完成项和风险 |
| W-06 | 任务失败时必须停止并报告 |
| W-07 | 不能假装成功 |
| W-08 | 不能自行进入下一步（必须等确认） |
| W-09 | 不能修改规则文档本身（除非用户明确要求） |
| W-10 | 不能在没有 Spec 的情况下开发功能 |

---

## 失败处理

遇到以下情况时**立即停止**：

| 情况 | 处理 |
|------|------|
| build 失败 | 修复后重试，最多 3 次 |
| 页面白屏 | 回滚修改，分析原因 |
| 类型错误 | 修复类型定义 |
| 无法确定影响范围 | 停止并请求澄清 |
| Spec 有歧义 | 停止并请求澄清 |
| 修改了禁止文件 | 立即回滚并报告 |
| 测试失败 | 不得声明完成 |

**绝对禁止**：
- 在失败时继续执行
- 假装成功
- 跳过验证
- 编造命令结果
